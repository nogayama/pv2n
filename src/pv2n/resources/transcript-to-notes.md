# Transcript to Notes



## Invocation Protocol

This file is an executable task specification.

Parameters are supplied using the following format:

```text
key=value
```

### Parameter Handling

1. Read all `key=value` parameters supplied in the invocation message.
2. Match each key against the options defined in this file.
3. Apply aliases before resolving option values.
4. If an option is omitted, use its documented default value.
5. If an unknown key is supplied, report an error.
6. If an invalid value is supplied, report an error.
7. If both an option and one of its aliases are supplied with conflicting values, report an error.
8. After resolving an option, its value may be referenced as `${<option-name>}` throughout this prompt.

### Parameter Options

#### Source File Option

- Option: `video=<file path>`
    A video file path. Used only to derive filenames — the video content itself is not read.
- The resolved value is available as: `${video}`
- This option is required.

#### Output Dir Option

- Option: `output=<dir path>`
    The directory where pv2n wrote its output files (VTT, frame images, transcript markdown, and where the note will be written).
- Default: `output=output`
- The resolved value is available as: `${output_dir}`

#### Output File Format Option

- Option: `format=<md or html>`
    The file format of output lecture notes.
- Default: `format=md`
- The resolved value is available as: `${format}`

#### Language Option

- Option: `language=<supported-language>`
    Any natural language supported by the AI agent is accepted.
    ISO 639-1 codes and common abbreviations are also accepted and resolved to their full language name before use.
    
    Example mappings (case-insensitive):
    | Supplied value | Resolved as |
    |---|---|
    | `en`, `eng` | `English` |
    | `ja`, `jp`, `jpn` | `Japanese` |
    | `zh`, `cn`, `zho` | `Chinese` |
    | `fr`, `fre`, `fra` | `French` |
    | `de`, `ger`, `deu` | `German` |
    | `es`, `spa` | `Spanish` |

    For any value not listed above, interpret it as a natural language name as-is.

- Alias: `lang=<supported-language>`
    `lang` is an alias for `language`.
- Default: `language=English`
- The resolved value is available as: `${language}` (always the full language name, e.g. `Japanese`, never a code)

```
run agents/skills/transcript-to-notes/SKILL.md video=video.mp4

```

If the user answers yes, incorporate the visual content of each slide image when crafting section titles and explanatory prose, and apply Rule 10a below.



## Task

You are given a transcript markdown file `${transcript_md_file}` and slide screen captures in `${frame_dir}`.
Your job is to produce a clean, well-structured summary document and write it to `${output_file}`.

Follow the steps below based on `${format}`:

**If `${format}` is `md`:**
1. Write the Markdown document directly to `${output_file}`.

**If `${format}` is `html`:**
1. First, produce the Markdown document following all Common rules and Markdown-specific rules — exactly as if `${format}` were `md`. Write it to `${output_dir}/${stem}.md`.
2. Then, convert that Markdown document to HTML following the Rules for HTML format. Write the final HTML to `${output_file}`.



## Input

- **Transcript Markdown File:** `${transcript_md_file}` — Spoken transcript text and key frame captures in markdown format.
- **Frame Dir:** `${frame_dir}` — This directory contains key slide images.
    - Slide images were captured at moments of significant screen change, so a single capture may interrupt a semantically continuous passage of speech.



## Output

- **If `${format}` is `md`:** Write the Markdown document to `${output_file}`.
- **If `${format}` is `html`:** Write the intermediate Markdown to `${output_dir}/${stem}.md`, then write the final HTML to `$output_file` = `${output_dir}/${stem}.html`.



## Rules

The following rules apply to all output formats. Format-specific rules are defined in the sections below.



### Common rules (all formats)

1. **Generate the output document in `${language}`.**
   When explaining content in `${language}` or any non-English language, retain the original English term for proper nouns, technical terms, product names, and industry-specific vocabulary — write the English word alongside (or instead of) any translation.

2. **Re-group content by semantic meaning, not by capture timestamp.**
   Because slide captures may cut across a continuous explanation, look at the narration before and after each image to determine the most natural grouping. Place each image at the point where it best represents the surrounding content.
   In presentation videos, diagrams and shapes are often revealed incrementally via animations; the frame captured is therefore the **final** state of that animation sequence, meaning the presenter may have started discussing the topic **before** the capture timestamp. Prioritise semantic coherence above all else.

3. **Add a brief introduction and a summary section** at the top and bottom of the document respectively, based on the overall content of the transcript.

4. **Do not invent information.** Everything in the output must be grounded in the source transcript.

5. **Generate a descriptive top-level title.** The first line of the output must be a top-level title element that summarises the overall content of the video in a concise, meaningful title — do not use the source filename.

6. **(vision only): Deduplicate visually similar consecutive frames.** Within each semantic section, if multiple consecutive slide images are visually similar to each other (e.g. the same slide with no meaningful change), keep only the single image whose visual content best matches the surrounding spoken transcript, and comment out the rest (using the comment syntax appropriate for `${format}`).
    The kept image must remain as a visible embed — do not comment it out. Images that differ meaningfully in content must always be kept as visible embeds regardless of proximity.
    This also relates to Rule 3: because frames are captured at the **end** of animation sequences, the capture timestamp may lag behind when the presenter actually started discussing that topic. When reading slide images directly, use the visual content to identify which stage of the animation is shown and align it with the surrounding narration more accurately — paying particular attention to the timing offset between the capture and the semantic content being discussed.

7. **(vision only): Etract information from frames** If the AI has the ability to read characters from the image, and if there is information in the image that is not in the transcription, extract it and reflect it in the notes. In particular, the table should be extracted even if it is mentioned by audio.

8. **If internet access is available, add a References section at the end of the document.** List official documentation and other relevant resources that cover the topics discussed in the notes in more detail. If there is a content in the lecture notes that we can understand the details by looking at the Reference, Add it with the link.

    **Example to add references**

    ```md
    ... Asset and Location are modules of Maximo Manage, and many other modules are available.
    
    > **Source Reference**
    > The built-in modules available for Maximo Manage are listed in [Modules and Applications](https://www.ibm.com/docs/ja/masv-and-l/cd?topic=91-modules-applications-in-maximo-application-suite).
    
    ## References
    
    1.  [Modules and applications in Maximo Application Suite 9.1 - IBM Documentation](https://www.ibm.com/docs/en/masv-and-l/cd?topic=91-modules-applications-in-maximo-application-suite) 
    ```



### Markdown-specific rules (`format=md` only)

2. **Preserve all image embed syntax exactly as-is.**
   Every `![Title](Filepath)` found in the source must appear unchanged in the output.

4. **Structure each subsection as follows:** Each subsection must have a `##` heading that reflects the content spoken while that slide was displayed, followed by the slide image (if one exists for that section), followed by explanatory prose summarising the speaker's intent in plain, easy-to-read language. Do not transcribe word-for-word. Use bullet lists or tables where they improve clarity.
   - If a section has a corresponding slide image, include it:
     ```
     ## <Title reflecting the spoken content for this slide>
     
     ![Slide image](video.assets/frame_00-00-19.667.png)
     
     Explanatory prose summarising what the presenter says while this slide is displayed.
     ```
   - If a section has **no corresponding slide image** (e.g. spoken content before the first screen capture), omit the image line entirely and write only the heading and prose:
     ```
     ## <Title reflecting the spoken content>
     
     Explanatory prose summarising what the presenter says.
     ```

7. **Avoid Markdown horizontal rules (`---`).** Do not use horizontal rules unless absolutely necessary for document structure.

8. **Insert three blank lines before each section heading.** Add three empty lines immediately before every `##` or deeper heading to visually separate sections.



### Language-specific rules (`language=Japanese` only)

J1. **文体は常体（だ・である調）を基本とし、可能な限り短く言い切る。**
    冗長な表現を避け、一文で完結させることを優先する。
    - 良い例：「この変数は整数型。」「設定は Database Configuration アプリで行う。」
    - 避ける例：「この変数は整数型となっています。」「設定はDatabase Configurationアプリケーションで行うことができます。」

J2. **見出し（`##` または `<h2>`）も常体・体言止めで書く。**
    動詞で終わる場合は終止形または名詞化する。
    - 良い例：「GL Account の概要」「コンポーネントの設定方法」
    - 避ける例：「GL Account の概要について」「コンポーネントを設定するには」



### Rules for HTML format (`format=html` only)

H1. **Use semantic HTML elements for document structure.**
    - `<h1>` for the top-level title, `<h2>` for section headings
    - `<img src="..." alt="...">` for slide images
    - `<p>` for prose, `<ul>`/`<ol>` for lists, `<table>` for tables

H2. **Preserve image file paths exactly.**
    Convert every `![Alt](path)` to `<img src="path" alt="Alt">` — do not modify the path value.

H3. **Output a complete, self-contained HTML file.**
    Start with `<!DOCTYPE html>` and include `<html>`, `<head>` (with `<meta charset="UTF-8">` and an embedded `<style>` block), and `<body>`.

H4. **Embed a minimal readable stylesheet in `<head>`.**
    Include styles for: body max-width and font, h1/h2 spacing, img (max-width: 100%), table borders, and code blocks.
    Do not use inline `style=""` attributes.

H5. **(vision only) Comment out duplicate frames using HTML comment syntax.**
    Use `<!-- <img src="..." alt="..."> -->` for commented-out duplicates (as referenced in Rule 10).

H6. **Do not use `<hr>` elements** unless absolutely necessary for document structure.
